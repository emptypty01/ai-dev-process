# 评审与发布约定

## 两轴评审

- 需求：逐条核对 AC、范围、业务边界与兼容规则，给出实现与测试证据。
- 规范：核对项目结构、Java 风格、事务、参数化 SQL、迁移与凭据处理。
- 指明审查的源 / 目标 SHA；未提交工作区按实际文件审查并标记，不伪造版本。
- AI 发现作为人工评审输入；编译和定向测试由确定性工具执行。

## 本地示例 CI/CD

- 普通 Runner 标签 `local-docker`：交接检查、定向单测、前端构建、后端打包。作业不持有 Codex 登录或 API 密钥，也不挂载 Docker socket。
- 发布 Runner 标签 `local-deploy`：仅接受受保护分支的手工作业；为本地可信示例挂载 Docker socket，实现镜像构建与 `ai-order-demo` 部署。该 Runner 不用于运行外部 MR。
- `deploy-local` 仅默认受保护分支可手工触发，环境地址 `http://localhost:5174`。
- 发布制品基于流水线 SHA；回滚需保留之前镜像，明确目标 SHA，重新设置版本并启动 Compose。数据库迁移不能靠镜像回滚自动撤销。
- GitLab CE Free 的批准不是强制审批门禁；通过禁止直接推主分支、限制合并角色和评审记录实施人工交接。
